# ベースと2xを組み合わせ、テンポを保ってつなぐ

`start-sync-box.cmd` を起動し、[パターン編集](http://127.0.0.1:8080/sync-compose.html) を開きます。最初は左タブの **基本モード** です。

1. **基本モード**の先頭にある **基礎パターン** のプルダウンから、**ボックス／シャワー／固定のダブルボックス／シャワー型のダブルボックス／ハイロー／4周期**を選ぶと、その基礎を再生します。固定のダブルボックスは中央コラムを保つ型です。4周期はBoxの**左→右→左→右**の2xを4つ独立に選べます。選んだ基礎に応じた編集欄で変更し、**再生**で反映します。以前の見本は **ほかの技を選ぶ** に残しています。Boxは **並びへ追加** で右タブへ渡せます。
2. **つなぐモード**では、編集中のベース名の横にある **ベースを変更** からHigh-Low・Shower・Double Boxを選びます。選択画面には日本語名、動きの特徴、設定する2xの数を表示します。選ぶと、その位置の技が変わります。High-Lowはハイの担当、同時に投げる2x、スワップの上下を分けて設定します。Double Boxは各セットの担当手を表示した4枚の2xカードを使います。
3. **＋ 技を追加** からベースを選ぶと、並びの末尾に新しい技が加わります。**技の並び**を開くと、カードの選択、前後移動、複製、削除ができます。並びにあるBoxは **基本モードでこのBoxを編集** → **並びのBoxを更新** で、位置と繰り返し回数を保って更新します。
4. **この並びを再生**で、末尾から先頭への戻りを含む周期を生成します。計算は別スレッドで行い、画面下の **生成を中止** から止められます。
5. **テンポ・保存・読み込み**から、全体のテンポ、左右反転、JSON保存・復元を操作します。編集中の並びも自動保存します。

スマホの縦画面では、上にプレビュー、下に編集欄を固定します。編集欄だけがスクロールするため、タブと再生・中止ボタンは常に操作できます。**拡大**でプレビューを広げ、**設定・状態**から速度・再生位置・軌道表示を変更します。スマホの横画面はプレビューと編集欄を左右に配置します。

動作例：[Box → Cross → High-Low → Shower → Double Box のJSON](examples/base-route.json)。13セットで動作が一周し、同じ球の配置まで39セットです。[検証概要](verification/base-route-release.json)。

## ベースの定義

| ベース | 選ぶ要素 | 基本の周期 |
| --- | --- | --- |
| Box | コラム配置、左手の2x、右手の2x | 2セット。Cross上下交代は4セット |
| High-Low | コラム配置、ハイと同時の2x、ハイを投げる手と固定／交代、スワップの上下 | ハイ＋2x → 両手の2xスワップ、を2回 |
| Shower | ハイを投げる手、2xの投げ方 | 1セット。2xの到着位置から高い球を投げ、2xの出発位置へ戻す |
| Double Box | 4xの球の軌道（Showerを挟む／4xも縦に投げる）、4セットそれぞれの2x | 4セット |

High-Lowのスワップは「左の2xが上／右の2xが上／交代」で、ハイの担当とは独立です。ハイの左右交代は6、同じ手に固定する場合は受け渡しを維持するため6xを用います。
Double Boxは手向きではなく、4xの球の軌道で2種類を区別します。**Showerを挟む**型は4xを弧で反対の手へ渡し、4で縦のコラムに戻ります。**4xも縦に投げる**型は4と4xの両方を真上に投げます。4xも投球・捕球のX・Z位置を同じにし、反対の手がその場所へ移動して捕ります。同じ手が続けて投げる場合も高い球の空間的なレーンを交互に使います。4xの「x」は受け手が替わる指定であり、球が横に飛ぶことを必須にはしません。
基本モードで **Extended Box / 中央コラムを保つDouble Box** などの技を選んだ場合も、2xの変更は元のコラム配置を保って反映します。4x側・4側はセットの番号ではなく、同時に投げる高い球の種類で区別します。開始セットを変えても担当は維持されます。
固定型・シャワー型のダブルボックスでも、**Normal / Switched / Cross / Underarm** を選べます。Crossは左腕が上・右腕が上・上下交代を指定します。Switchedは高い投げを反対側へ、Crossは2xも反対側へ配置し、体をまたぐ幅を共通の比率で狭めます。UnderarmはSwitchedと同じ位置に高い投げを置き、その腕を2xを投げる腕の下に通します。2xはBoxのUnderarm（Threaded Box）と同じく高めに投げて中央で捕ります。縦の2x（Inside・Center・Outside）は、BoxのUnderarmでも位置と高さを変えずに縦のまま投げます。中央の4xは中央に残り、縦の投げは腕の上下による奥行き差を補正して同じ縦線で捕ります。配置と2xは別々に編集でき、Normalへ戻すと元の幅に戻ります。つなぐモードのDouble Boxでも同じコラム配置を選べます。
Showerでは高い弧と2xの両端を対応させます。Lateralなら高い弧の両端も一緒に反転します。

2xはNormal（下→下）、Shuffle（上→下）、Reverse Shuffle（下→上）、Inverted（上→上）、それぞれのLateral、Inside・Center・OutsideのColumn Up/Downから選びます。手前／奥は2xの進行方向で先に通る球／後に通る球です。Showerでは独立した2本のコラムに対する上下判定を適用せず、選んだ2xの両端に高い弧を対応させます。

縦の2xの境界は、2本のボールの縦軌道「│ │」。**Inside** は投げる手と同じ側の外側、**Center** は2本の間、**Outside** は投げる手と反対側の外側を指します。左右は演者を基準にし、左右反転した再生でも手に対する関係を保ちます。旧表示のCross sideを廃し、保存済みの軌道は位置を変えずにこの定義で呼び分けます。

Double Boxの基本モードでは、4xと同時の2xと、4と同時の2xに、それぞれNormal・Shuffle・Reverse Shuffle・Invertedと各Lateralを選べます。Lateralはその2xの投げ・捕りの位置を左右反転する指定で、高い4/4xの軌道やテンポは保ちます。中央の端点は中央に残ります。つなぐモードでは4セットそれぞれに同じ指定を使えます。


## 直接移行

投球時刻と各セットの長さを保ち、技の境目をまたぐ球を、受け手の次の投球位置で捕るように投げます。捕球の手向きも次の投げへ合わせます。手を運ぶためだけの移行セットは追加しません。球の受け渡し予定が異なる場合のみ、最短の受け渡しセットを補い、画面に追加数を表示します。末尾→先頭も同じ規則です。

元の選択と、生成後の移行軌道は別に扱います。境目の投げは次の技へ届く移行軌道となり、その瞬間まで元の単独技と完全に同じ軌道を強制しません。球の上下・投球時刻を保ちながら、腕の届く範囲に応じて全体の横幅と奥行きを共通倍率で縮めます。倍率は最大5候補で決め、技名別の補正は追加しません。

腕は直接移動・小さな円・引き込みの最大5候補から生成します。接触を許す簡易再生を明示し、球の所有関係と有限の座標、手と球の接続は検査します。接触・姿勢の近似が残る場合を、厳密な無干渉の動作と区別します。

保存形式は `kind: sync-base-route, version: 1`。共通の `beatDuration`（1拍の秒数）、`mirror`、各技の `parts` と `repeats` を持つ `blocks` を記録します。1セットは2拍です。最大16技、各1〜8回、生成後64セットまでです。

**基本モード**には従来の詳細編集を残しています。登録した動作を変更せずに接続する旧方式は、つなぐモードの **登録済みの接続・1セットずつの詳細操作** にあります。以下はその既存機能の設計と検査記録です。

# セット列で同期パターンを作る

`start-sync-box.cmd`で起動し、見本画面の「セットで組む」を開く。
直接開く場合は [セット編集画面](http://127.0.0.1:8080/sync-compose.html) を使う。
左右それぞれの投げを1セットにまとめ、セット列全体から球の受け渡しと手の移動を計算する。

## 相対通過と、次の投げ位置への移動

「手前・奥」は2xの進行方向で先に通る球・後に通る球を指す。Shuffleは手前の球の上→奥の球の下、Reverse Shuffleは下→上、Normalは下→下、Invertedは上→上。手の絶対的な高さでは定義しない。

基本部品はこの通過条件を持つ。2本の球の横位置を順に横切る2xについて、実際の交差時刻と相手の球の高さから投げ・捕球位置を解く。左右反転、列の順序、周期長にかかわらず同じ計算を使う。2列を横切らない縦・内側の経路を、この検査だけで正しい技と認定しない。

捕球位置と次の投球位置の間には、球を保持した手の移動を作る。干渉時は途中の経由位置を探索し、相対指定の動作では捕球時刻・コラムの高さ・作業位置も候補にする。球が空中にいる区間は常に解いた放物線を使い、手の経路修正で空中の球を曲げない。同じ境界状態が繰り返される区間には同じ経由位置を提案し、全周期で確認する。

移行は生成済みの実際のA・Bから作る。元の未解決の座標ではなく、捕球時刻、保持・空手の経由位置を含む状態を取り出す。投げ順が同じ場合は途中の投球位置と前後の迂回候補を挿入する。登録済みの入口・出口は再時刻設定せず、球・手・腕と両側の速度まで一致した接続だけを再利用する。

移行中の球が干渉する場合は、生成した区間の投げ・捕り位置も探索する。登録済みのA・Bは固定し、コラムは投げと捕りを一緒に移し、2xは両端を独立に動かして放物線を解き直す。捕球後の運びは新しい終点と次の始点から再構成する。技名ごとの調整表は増やさない。

「球同士の接触を許可する」を選ぶと、球間隔だけでは再生を拒否しない。2xの通過の上下関係、受け渡し、手の間隔、腕の到達範囲、胴体・腕どうし・球と腕の干渉は引き続き検査する。接触がある周期には画面に「球同士の接触あり」と表示する。設定は基本のJSONと接続列JSONに保存され、構造コードにも反映される。設定のない既存ファイルは従来どおり接触を禁止する。異なる設定の技を接続する場合、生成する移行ではどちらか一方の接触許可を引き継ぐ。登録済みの元の動きは変えない。

探索は有限であり、失敗を技の不可能性の証明には使わない。Normal・Switched・Underarmの基本2x各16組合せ、Normal BoxとSwitchedの左Inverted・右Shuffleとの往復を付属VRMで検査した。往復は球の接触禁止・許可の両方で生成・保存・復元できる。Cross左上の基本16組合せは4組が生成でき、残り12組は接触許可でも腕の条件で未解決である。すべてのLateral・縦・保持2との混合も、この共通処理での全対応を確認できていない。従来の個別見本・保存済みの明示座標も残している。今回の証拠と制限は[検査記録](verification/sync-contact-and-transition-audit.json)にまとめる。

## 画面の2つのモード

**基本モード**は「コラム × 2x」で選ぶ。コラムはNormal・Switched・Cross・Underarmの4系統。Crossの左上・右上・交代は別に選ぶ。左右の2xにはNormal・Shuffle・Reverse Shuffle・Inverted、各Lateral、縦のInside・Center・OutsideのUp/Downを名前で表示する。「下→上」などは補足であり、選択名ではない。既存の空間経路の見本に一致する組合せは、その見本を初期位置として使い、相対通過の指定がある区間を共通処理で解く。

選択を変えると編集内容が切り替わり、「再生」で動きを生成する。既存の技名と組合せの内訳を区別し、詳細な位置・手向き・保持2・4x・Doubleは展開して編集する。球の受け渡しが合っていても動作生成が失敗した場合は「この動きはまだ再現できていません」と表示する。これは有限の候補探索で経路を見つけられなかったという意味であり、技が不可能という判定ではない。失敗の詳しい理由は折りたたみ内に残し、直前のプレビューを保つ。

**つなぐモード**には基本モードの「＋つなげる」から追加する。既存の同じ動作と接続を再利用し、接続が不足する場合だけ移行を生成する。追加する動作は列のテンポで再検査する。「この順番で再生」で必要な先頭への戻りも加える。生成に失敗した場合、追加・再生前の列を保つ。登録庫・一括準備・手動移行・開始セットの指定は詳細欄に残す。各カードには実際に含まれるセット数を表示する。

両モードの編集内容は切替時に保持する。プレビューは最後に再生した内容を保ち、編集中の内容と異なる場合はその旨を表示する。画面下のボタンは、現在のモードと成立性に応じた次の操作を示す。構造コード・保存内容ID・1セット単位の接続操作は詳細欄にまとめる。これらのIDを技の呼び名としては使わない。

名前による分類と自動接続の検証は[名前で組むUIの記録](verification/sync-compose-named-parts-audit.json)を参照。前版のモード分離・左右反転などの検証は[モード分離の記録](verification/sync-compose-modes-audit.json)に残す。数学的に有効な投げ順を作れることと、すべての組合せの球・腕を再現できることは別である。

## 接続を再利用するための完成条件

対象は、基本動作を1セットずつ組み合わせ、別の動作へ遷移し、閉じた周期として再生できる編集器である。
技名や完成したセット列を一つずつ登録し終えることを完成条件にはしない。資料は、基本動作の不足や定義の間違いを見つけるために使う。
同じ基本動作と接続から作れる新しい列は、その定義と接続を再利用する。

1. **基本動作を表現できること。** 投げる位置→通る位置→捕る位置→次の投げる位置を基本とし、2xの高さ4分類、コラムの担当側、クロスの左上・右上・上下交代、投球・捕球それぞれの腕下と手向き、保持と空の手の運びを独立した指定として扱う。4x、保持2、自己投げ2T、ハイローも同じセット列に含める。In-line 3は保持中を含む常時縦一列という条件を保つ。独立して指定できることと、すべての指定が同時に成立することは区別する。
2. **成立した接続を再利用できること。** 技名ではなく、入口と出口の状態を接続の条件にする。A→BとB→CのBが同じ境界状態なら、検査済みの区間を保持して組み立てる。球の到着順だけが同じ場合は再利用の根拠にしない。Bへの入り方が違う場合は境界状態も別として扱い、必要な移行区間を生成・検査する。
3. **編集画面で組み立てと周期を確認できること。** 次に置ける動作、必要な移行セット、不成立の理由を表示し、列の最後から先頭への戻りも成立させる。動きが戻る周期と同じ球まで戻る周期を区別する。保存・復元・左右反転を含め、実際の画面と再生で確認する。

接続状態には、左右どちらの手か、保持球、飛行中のすべての球の位置・速度・到着先・残り時間、手の位置・向き・速度、腕の姿勢、クロスや腕下の関係を含める。
境界をまたぐ保持・空の手の移動も接続条件に含め、組み立て後に前後の技に合わせて検査済みの軌道を作り直さない。
球の色は対応する球の入れ替わりとして引き継ぎ、その置換から球識別の周期を求める。
使用モデル、テンポ、球の大きさ、座標や運びを変更した場合は接続条件が変わるため、影響する区間を再検査する。
位置だけを丸めて同一状態とみなしたり、保存データの自己申告だけで検査済みとみなしたりしない。

この条件が成立すれば、検査対象は基本区間と新しい接続になり、可能な長い列をすべて列挙して個別に検査する必要はない。
同じモデル・テンポなどの条件で、対象とする各入口状態から共通の基準状態へ行き、そこから戻れる接続網を作れば、全ての動作の組に専用の直接移行を用意する必要もない。たとえばB→AとA→Cが検査済みなら、B→A→Cを使える。往路の成立だけから復路の成立は推定しない。複数の開始局面やクロスの上下を別の入口として扱い、未接続の入口と出口を完成までの作業対象にする。
通常のセット編集は、受け渡し順の状態探索と、組み立てた列全体の球・骨格検査を行う。
`connectSequenceCycles`の成立は受け渡し順の成立であり、空間的な接続の再利用を証明するものではない。
この経路の`prepareSyncCycle`は列全体の腕経路を再計算する。
別に「検査済みの接続部品で組む」では、登録時に検査した実際の軌道と肘の経路を保持し、入口・出口の一致する区間を再利用する。
再利用列では、列全体の腕経路探索を実行せず、元の区間の補間をそのまま再生する。再生中の各姿勢の制約検査は保つ。
完成時の検証では、基本動作の各指定、同じ接続を使う複数の長い列、最後から先頭への接続、異なる入口やモデル・テンポ変更時の再検査を確かめる。
骨格による判定の範囲と、描画・衣装・人間の実演への一致の確認範囲は引き続き区別する。

## 検査済みの接続部品で組む

基本部品から始める場合は、「準備する部品」でグループを選び、**「選んだ部品と移行をまとめて準備」**を押す。
「高低・空間経路・Double / 90動作」を選ぶと、通常、Switched、腕下、クロスの高低の組合せ56定義、縦2xなどの空間経路18定義、基本Doubleの16定義と、その接続を準備する。
現在のモデルと選択中の左右反転で検査し、登録庫が空なら1セット0.41秒、すでに3球の登録がある場合はそのテンポを使う。
別のモデルやテンポで全件が通ることを保証するものではない。

「HFの腕下・クロー・役割固定 / 11動作」を選ぶと、次の動作を1セット0.5秒で準備する。

| 動作のまとまり | 登録する動作 |
| --- | --- |
| つなぎにも使う動作 | 通常Box、Reverse Shuffle、Box Roll |
| 腕下の投げ・捕球 | HF Under-Arm-Box*、Reverse-Under-Arm-Box*、Reverse-Under-Arm-Inverted-Box* |
| 左2xの役割固定 | 通常、Inverted、HF Reverse-Under-Arm-Inverted-Box |
| クロー捕球 | HF Under-Arm-Claw-Box*、Double Under-Arm-Claw-Box（セット3から） |

各動作を通常Boxへ往復できるように登録する。
左右反転を選ぶと、役割固定の2x側も反転する。
別のテンポで登録済みの場合は、現在の接続列をJSON保存し、「登録部品をクリア」してから準備する。
すでに1セット0.5秒・3球の部品がある場合は、その登録庫に追加できる。

画面に、90動作では179段階、腕下・クロー・役割固定の11動作では21段階の進み具合と、検査中の動作または移行を表示する。
数分かかる場合があり、「準備を中止」で止められる。
検査中の部品は仮の登録庫に置き、全件が通った時だけ追加する。
中止や失敗では、元の登録庫、接続列、プレビューを保つ。
同じ定義と左右反転が登録済みなら再利用するため、2回押しても部品や移行を重複登録しない。
4球の登録庫とは混ぜず、準備中にモデルや登録内容が別の操作で変わった場合も反映を止める。

同じ動きを繰り返した長い列はそのまま残し、移行に使う2セットの基本周期を別に登録する。準備に通った定義は左右2xの組合せ表にもチェックを付ける。テンポや左右反転が異なる定義へ、その結果を流用しない。

「登録動作の接続状況」で基準の動作を選び、「接続状況を確認」を押すと、基準から各動作の開始セットへ行き、一周して基準へ戻れる範囲を表示する。
行きと戻りには、直接つながる場合は0、別の区間を挟む場合は追加の移行セット数を表示する。
「開始セットごとの接続を表示する」は初めから有効で、先頭からの往復と、全開始位置での往復を別々に数える。同じ姿勢に戻る開始位置が複数あっても、セット番号ごとに表示するため、異なる状態の総数ではない。
最初は未接続の開始位置だけを表示し、チェックを外すと接続済みの開始位置も確認できる。「開始セットごとの接続」を外すと各動作の先頭だけを表示する。
接続済みの行の「この開始位置を選ぶ」は、追加欄の動作と開始セットを選ぶ。現在の列への移行と周期をそこで確認してから追加する。
未接続の行の「移行を準備」は、基準とその動作を移行作成欄に選ぶ。
「移行を検査して登録」で不足する接続を準備した後、もう一度接続状況を確認する。

この一覧は技名や代表状態の番号ではなく、実際の接続探索と同じ球・手・腕の境界状態で判定する。
経由する動作を含めて片道128移行セットまで探し、腕の再計算や新しい動作の登録は行わない。
元の動作の長さと球の入れ替わりも含む完成列の周期は、追加・先頭への戻りを行う時に別途確認する。
登録や列の変更後は一覧を消し、古い判定を現在の結果として表示しない。

画面上部の「登録した動作をつないで周期を作る」から接続欄を開く。準備後は「次の動作を追加」で動作、開始セット、1〜16回の回数を選ぶ。現在の末尾から選んだ入口への移行を登録済みの経路から探し、追加する移行・動作のセット数と、先頭へ戻した場合の周期を表示する。選択や追加で腕の探索・新規登録は行わない。移行がまだない場合は追加できず、別途「移行を検査して登録」で準備する。

開始セットを変える場合は、登録した区間を循環順に並べ替える。例えば4セットの区間をセット3から始めると、3→4→1→2の順で一周する。元の球・手・肘の軌道を保持し、一周した出口からの戻りも改めて調べる。選択欄の番号は同じ球まで戻る登録区間を含むため、動きの最小周期より多い場合がある。接続列の保存には実際の区間順を記録し、読み込み時も選んだ開始位置を再現する。

付属VRM・1セット0.5秒のBoxとBox Rollでは、Box Rollのセット1からの往復は行き6・戻り6セット、セット3からは行き4・戻り4セットとなる。BoxとBox Rollの全14開始位置を左右それぞれ確認し、元の姿勢と球の対応を保った。開始位置を変えて組んだ38セットの列は同じ球まで114セットで閉じ、保存・復元後も240時点の姿勢が一致した。結果は[開始位置別の再利用検査](verification/sync-entry-reuse-audit.json)に保存する。追加した選択欄と一覧の実画面は未確認である。

追加は現在の列を保って末尾へ行い、「直前の追加・変更を戻す」で移行を含む追加全体を取り消せる。新しく生成した移行用の区間は、通常の動作の選択肢から除き、チェックを付けた場合に表示する。この区別は接続列JSONにも保存する。以前のJSONには区別の情報がないため、すべて動作として表示する。表示上の区別で検査を省略することはない。

「先頭への戻りを補う」で表示されたセット数の戻り道を加えると、動きの周期と同じ球まで戻る周期が確定する。1回の区間に含むセット数は選択欄に表示する。1セットずつ組む場合は「1セットずつ選ぶ」を開く。見本や編集した動作を個別に加える手順は次のとおり。

1. 基本モードで「選んだ動きを編集欄に入れる」、または見本の「この見本を編集」を押す。
2. 「成立を確認して再生」で確認し、「確認した動作をつなぐモードへ」を押す。接続先の条件に合わせて再検査し、登録できるとつなぐモードへ移動する。
3. 別の列も同じモデル・球数・テンポで登録する。登録済みの入口と球・手の状態が同じなら、新しい列の肘をその入口に合わせ、調整後の新しい列を実VRMで検査する。以前の部品の経路は変えない。
   登録庫の球数と1セットの時間を画面に表示する。「新しい部品・見本を、登録済みのテンポで検査する」を選ぶと、新しく登録する定義の時間をそろえて再検査する。元の見本、編集中の列、既存の登録区間は変更しない。新しいテンポで検査が通らない場合は登録しない。
   単独周期同士に共通の入口がない場合は「別の動作への移行を作る」で動作A・Bを選び、「移行を検査して登録」を押す。登録済みの経路で往復できれば、それを再利用する。まだつながらない場合だけ、元の周期を繰り返して安定した入口を確保し、受け渡しのつなぎを含む移行候補を生成・検査する。
   「この2つで往復列を作る」を押すと、Aの一周→AからBへの移行→Bの一周→BからAへの移行に置き換える。移行の検査だけでは編集中の接続列やプレビューを変えない。
4. 「接続列を空にする」で空の列から始め、「次の動作を追加」で区間を並べる。1セットずつ選ぶ場合の候補は、現在の出口に一致するものだけになる。
5. 「先頭への戻りを補う」で、登録済みの部品から戻り道を探す。「この周期を再生」で、保持した動作区間を再生する。
6. 接続列に名前を付け、「接続列をJSON保存」で保存する。登録や列の変更はブラウザーにも自動保存される。閉じていない作りかけの列も保存できる。
7. 「接続列JSONを読み込む」または「自動保存した接続列を戻す」で復元する。現在のモデルで各元動作を再検査するため、時間がかかる場合がある。復元後は「この周期を再生」を押す。

入口の照合には、球の位置・前後の速度・保持する手・到着先・捕球と次の投球までの時間、両手の位置と向き、肘の位置と前後の速度、クロスと腕下の条件を使う。
捕球ちょうどの時点では、サンプル番号の丸めで保持が1フレームずれることを避け、到着イベントから保持する手を判定する。
数値計算の誤差の範囲だけを許容し、位置の近さだけでは接続しない。球の色の違いは対応する球の置換として引き継ぐ。
たとえば、同じ状態へ戻る役割固定の1セットは、球を入れ替えながら再生し、3セット後に同じ球の配置まで戻る。
画面のセット数は組んだ列を一周する長さであり、同じ区間を繰り返して追加した場合も入力した回数を保つ。

共通の入口へ合わせる際は、新しく登録する区間の境界近傍だけで肘の経路を補間し、腕の長さに合う位置に置く。その変更を含む周期検査に失敗すれば登録しない。
登録済み区間の単なる連結ではこの調整を繰り返さない。入口が異なる場合は候補に出さず、新しい移行区間が必要になる。
球と手の中心軌道は登録前の列から保持する。In-line 3の縦一列や腕下のイベント指定も区間内に保持する。

移行の自動生成は、両方の元周期を2回、必要なら4回ずつ並べた候補を検査する。受け渡し順だけでなく、既存Aの出口から新しい区間へ入れること、既存Bへ到達すること、その逆も実際の境界状態で確認してから登録する。
検査が通らない候補は登録庫を変更しない。失敗は人間にも不可能という判定ではなく、この自動配置では成立しないという意味である。「調整用の移行を編集欄へ」で候補を読み込み、投げ・捕り・運びを修正できる。候補の左右反転と、球の間隔・届く範囲などの発生箇所も引き継ぐ。取り込みだけでは候補を再生・登録しない。修正後に通常の「成立を確認して再生」と登録を行い、動作A・Bの移行をもう一度調べる。行数・球数・テンポ・左右反転の制約も維持する。
たとえばBox↔InvertedとBox↔Reverseが登録されていれば、Inverted↔ReverseはBoxを経由できる。3種類の巡回順を変えるたびに新しい腕の経路を探索する必要はない。

In-line 3を含む場合は、縦一列の入口・出口を移行候補に加える。登録済みの動作のテンポは変えない。通常Boxとの移行はIn-lineの基準となる1セット約0.253秒で確認しており、0.32秒の候補は検査で拒否する。In-lineを先に登録し、通常Boxを登録済みのテンポで検査すると、同じ登録庫で移行を作れる。

「In-line 3 / 上の2x（候補）」も、同じ手順で通常Boxとの往復を作れる。
この見本を先に登録し、通常Boxを登録済みのテンポで検査してから、2つの動作間の移行を登録する。
上側へ入る20セットと戻る22セットを加えると、両方の元動作を含めて46セットで閉じる。
移行中は短いパスを左右へ広げ、上段へ移った後に体へ寄せる。
空の手は、上側In-lineの見本で使う外回りへ段階的に移す。
In-lineの区間では、球を持つ手も縦線上に保つ。
元の見本の座標と手向きは変更せず、保存後の復元と再利用を左右両方で確認した。
関連392件の検査結果は[上側In-lineへの接続記録](verification/sync-inline-upper-audit.json)に残す。
役割固定への受け渡しは1セット0.41秒、High-Low Boxは0.36秒、Box Rollと腕下クローは0.50秒、4球同期ファウンテンと4球コラムは0.41秒で、元動作を保つ移行を左右両方で検査する。これらの時間以外での成立を意味しない。

High-Low-Around Inverted Boxには、1セット0.30秒のHigh-Low Box / Swap Boxを中継する。
Aroundを先に登録してそのテンポを採用し、High-Low Boxと通常Boxを「登録済みのテンポで検査する」で登録する。
通常BoxとHigh-Low Boxの往復を登録した後、通常BoxとAroundの移行を選ぶと、High-Low BoxからAroundへの接続を生成して検査する。
元の2つの動作の位置や運びを置き換えず、すでに成立した往復と新しい移行をつなぐ。
中継動作は、移行相手と同じ投げ順を持ち、もう一方との往復が登録済みである場合に候補になる。
投げ順の一致だけでは登録せず、全区間の球と腕、両端の状態を検査する。
High-Low Inverted Boxと通常のInvertedの往復は、1セット0.36秒で確認する。

先頭への戻り道は、球の入れ替わりも含めて探す。
最初の戻り道で球識別の周期が128セットを超える場合も、登録済みの区間を足して上限内で閉じられるか調べる。
たとえば役割固定を43セット並べると同じ球まで戻るには129セットになるが、2セットを足せば45セットで同じ球へ戻る。
元の列と128セットの上限を保ち、追加の腕の探索は行わない。
接続と保存後の再利用、戻り道の検査は[High-Lowの接続記録](verification/sync-high-low-network-audit.json)に残す。

通常BoxとThreaded Boxは、単純な連結に失敗した場合、4xでコラムの受け手を交替し、短い球を2で保持する移行を追加で検査する。入口は`(4x,2x)(2,4x)`、戻りは`(2x,4x)(4x,2)`を使い、Threadedの2セットは循環順を保って開始側を入れ替える。戻りでは捕球直後から保持球を外へ運び、上昇中のコラムと前腕を離す。元の両技を変えず、1セット0.41秒で左右両方の登録・保存復元・経路再利用を検査する。この候補は対応する元の動作定義が一致する場合だけ使い、名前が同じでも位置や手向きを編集した列に無条件では適用しない。候補の生成後にも、使用中のモデルとテンポで全区間・両方向の接続状態を検査する。

### 基本6設定の接続網

3球・1セット0.41秒・付属VRMでは、各コラム設定の標準2xを次の5つの往復で接続できる。左右反転も同じ範囲を検査する。

| 登録する往復 | 移行の方法 |
| --- | --- |
| 通常Box ↔ Switched | 4xでコラムの受け手を交替し、2を外側で保持する |
| 通常Box ↔ クロス左上 | 下側の手から移行を始め、戻りの保持球を上側へ運ぶ |
| 通常Box ↔ クロス右上 | 左上と対称の順序で受け渡す |
| 通常Box ↔ Threaded | 受け手を交替し、保持球を捕球直後から外へ運ぶ |
| Switched ↔ クロス上下交代 | 担当する手を保ち、準備区間・高い2x・外側の運びで配置を変える |

一括準備を使わず個別に用意する場合は、左右の2xを「下→下」にしてコラムの6設定をそれぞれ「この部品を検査して登録」するか、対応する見本を登録する。「別の動作への移行を作る」で上表の5組を順に検査・登録する。その後は、たとえば左上クロスと上下交代クロスを選んでも、登録済みの経路を探して往復できる。

この6動作間の30方向では、新しい移行を追加せず経路を見つけられることを検査する。左上クロス→Switched→上下交代クロス→右上クロス→Threaded→通常Box→先頭という巡回も、腕の経路を新しく探索する処理を禁止した状態で検査する。元の6動作の定義は保持する。結果は[接続網の検査記録](verification/sync-component-graph-audit.json)の`networks`に保存する。

上下交代への配置移行では、保持球の運びが次のセットまで続くことを扱う。短い投げの2回目だけが次の配置段階に入るため、その捕球後の運びに外側の経由点を置く。1回目にも同じ大きな運びを付けると到達範囲を超える。元の上下交代の周期と開始側は変えない。

### 高低と空間経路にDoubleを加えた接続網

同じ3球・1セット0.41秒・付属VRMで、初期配置が成立する56部品も一つの接続網に登録できる。通常16、Switched16、腕下16、上下交代クロス4、左上固定・右上固定の各2である。左右反転でも同じ範囲を検査する。

基本6種類の接続を用意した後、追加する部品を登録し、同じコラム設定の標準2xとの移行を選ぶ。Switchedの両手Shuffle・両手Invertedには通常Boxを、上下交代の両手InvertedにはSwitchedを経由する候補がある。中継する動作が登録済みで、選んだ動作との往復経路がある場合にだけ、その先の接続を生成・検査する。画面には新しく使った中継動作を表示する。移行が登録された後は、別の組を選んでも既存の経路を使える。

上下交代のNormal/Inverted混合では、途中の高さと外側の運びを段階的につなぐ。左と右を入れ替えた混合では、元のクロス開始局面を保ったまま、移行を始める手も入れ替える。両手Invertedの低いコラム配置では、入口と退出直後のクロス指定を保持し、手の座標だけを移して肘の候補を変えてしまうことを避ける。

高低の56部品に、次の空間経路18部品を加える。内訳は、通常／Switchedそれぞれの中央・外側・反対側での縦上／縦下の12経路、横送りの4経路、腕下から投げる／腕下で捕る2経路である。元の37見本の座標・手向き・運びは変更しない。中継する部品との往復を一度登録すれば、接続済みの他の部品にも同じ経路を使える。

| 追加する経路 | 接続に使う部品 |
| --- | --- |
| 中央の縦上・縦下、反対側の縦上・縦下 | 通常Box |
| 外側の縦上 | 反対側の縦上 |
| 外側の縦下 | 反対側の縦下から、投げ・捕り位置と手の運びを段階的に移す |
| Switchedの外側の縦下 | 通常の外側縦下から、4xと保持2でコラムの受け手を交替する |
| Switchedの外側の縦上 | 中央の縦上 |
| Switchedの中央の縦上・縦下 | Switchedの両手Inverted |
| Switchedの反対側の縦上 | Switchedの中央の縦上から、移行中の2xを高くし、空の手を左右へ分ける |
| Switchedの反対側の縦下 | Switchedの反対側の縦上から、内向きの肘設定を保ちながら投げ・捕りの高さを入れ替える |

| Shuffle lateral | Inverted lateralから捕球高を移し、空の手を左右へ分ける |

## 基本動作の対応範囲

2xの高さの基本は4種類、縦の上投げ・下投げを加えた入口は6種類である。位置や運びは連続量なので、6種類で全動作を数え切るという意味ではない。コラム側は部品欄の4系統・6選択肢を入口にし、各セットでは腕の上下、投球時と捕球時の腕下、手向きを別に指定する。

| 分類する軸 | 指定できる内容 | 実装・検査の根拠 |
| --- | --- | --- |
| 短い投げの高さ | 下→下、上→下、下→上、上→上、縦上、縦下 | `ShortStyle`、既存37見本の球・手・骨格検査 |
| 短い投げの場所 | 中央・外側・反対側、lateral、任意の投げ・捕り座標 | `ShortMotionOptions`、縦2xの各レーンとlateralの見本 |
| 球の受け渡し | 反対の手へ2x、同じ手へ2T、持ったまま2、空の手0 | `throws`、Bizarre・Box Roll・3球コラム |
| コラムと高い投げ | 位置と担当する手を分離、4と4x、ハイローの6、4球の8 | `columnMotion`と各手の`definition`、Double・High-Low・Stackedの検査 |
| クロス | 左上固定、右上固定、上下交代、開始局面 | `armOrder`と`armPhase`、3種のクロスと途中セット取り込みの検査 |
| 腕の下 | 投げるとき・捕るときを別に指定、2側にもコラム側にも適用 | `release.relation`と`catch.relation`、短い投げ2種・Threaded・Underarm Box |
| 手の向き | 動作に合わせる、投げと捕りそれぞれ下手・クロー | `releaseGrip`と`catchGrip`、独立した手向きの骨格検査とLevels |
| 持った球の運び | 直接・内・外・前・奥、時刻付き経由点 | `carry`、Box Roll・Penmanと経路編集の検査 |
| 空の手の戻り | 持った球と別の方向・大きさ・経由点 | `emptyReturn`、Bizarre・Penman |
| 捕球時刻 | 通常、頂点、次の投球までの時間に対する割合 | `catchAtApex`と`flightFraction`、Levels |
| 同一平面の縦一列 | 保持中を含め3球を常に同じ縦線に置く | `arrangement: inline`、全周期の球中心の検査 |
| 周期と役割 | 左右交代、役割固定、Double、行ごとの回数と任意の列 | セット列解析、球識別の置換、保存・復元・接続検査 |

単独周期の登録と、異なる動作への移行は別に検査する。基本動作の登録庫では、既存37見本に、2T・ハイロー・保持と空の手の経由点・頂点捕球・空の手0を補う9見本を加え、左右反転を含めて実VRMで登録する。元の周期の再利用と、別の元動作へ直接つながる境界数を記録する。
またBox・Inverted・Reverseの3動作では、必要な2組の移行を登録し、3組目の接続・巡回順の変更・保存復元を既存区間だけで実行する。[基本動作と移行の測定記録](verification/sync-component-graph-audit.json)を参照。
この対応表は指定した動作軸の実装範囲を示す。全座標の組合せが干渉せずに成立すること、未確認の実演と一致すること、未登録のすべての移行を自動生成できることを保証するものではない。

## セットの組み立て方

「部品から組む / コラム × 2x」では、コラム側の動きを選び、左右の2xを4×4の表から選べる。
下→下、上→下、下→上、上→上の4分類を左右で組み合わせるため、左右を区別した16通りとなる。
選択時に生成予定の投げ列、球数、動きの周期、同じ球まで戻る周期を表示する。
保存内容が既存の見本と一致するときは、N-Boxなどの見本名も表示する。

コラム側は通常・反対側担当・クロス・腕の下で捕る、の4系統に整理する。
クロスの左上・右上・上下交代を別々に指定するため、画面では6つの選択肢になる。
6×16の96通りについて投げ列を生成できるが、初期配置で再生できるかは球・手・腕の検査で判定する。
前版の画面で確認した47通りに、腕下Shuffleの7通りと固定クロスの2通りを加えた現行の対応範囲は次のとおりである。

| コラム側の選択 | 初期配置の成立 | 調整が必要 |

| 通常 | 16 | 0 |
| Switched / 反対側担当 | 16 | 0 |
| クロス / 左腕が上 | 2 | 14 |
| クロス / 右腕が上 | 2 | 14 |

Switchedは左右の4種を組み合わせた16通りが初期配置で再生できる。

既存の見本に対応する部品は元の位置・運びを保つ。別の2xを指定したときは、古い投げ方の位置定義を残さず変更を反映する。

接続できない場合は、球どうしの間隔、左右の手の間隔、手の到達範囲、受け渡しの重複、腕の経路を区別して表示する。
腕の経路については、両腕の間隔、クロス・腕下の関係、片腕の到達範囲・曲げ方、球と腕の間隔、各時点の姿勢をつなぐ経路の不足に分けて返す。腕どうしの間隔が不足した場合は、検査した姿勢の最大間隔と検査基準をcmで表示する。これは現在の配置と肘候補に対する測定値であり、人間の動作としての実現不可能性を証明するものではない。
検査時刻がわかる問題には、発生した時間帯のセット・繰り返し回数・左右交代した区間と、周期内の秒数・割合を添える。

失敗した列の時刻を、表示を維持した前のプレビューの時刻と混同しない。編集を変更すると古い診断を消し、再検査で更新する。
固定クロスの高い捕球では、既定の横よけと保持中の外向きの運びが手首を身体の同じ側へ戻していた。

明示した運びの指定は使えるが、成立するかは検査する。
残る40通りの不成立は、人間が実現できないという判定ではない。
クロス左上の左Shuffleを調べた候補では、両腕単独には球を避ける姿勢があっても、同時に組むと腕の最大間隔が約6.6〜6.8cmに留まり、8cmの検査基準を満たさなかった。肘候補を36方向から72方向へ増やしても、この候補の不足は解消しなかった。高さ・前後の配置や手の戻りを変えた候補はまだ採用しておらず、40設定の未対応は残る。失敗理由の伝達と正常なプレビューの保持は[腕の制約の検査記録](verification/sync-arm-constraints-audit.json)に保存する。

再生を試した組合せは、表に「✓ 再生確認」または「! 調整が必要」を表示する。未検査は「○」、未検査の選択中セルは「●」で示す。
結果はその画面で使用中のモデルと左右反転の条件ごとに扱い、モデルの読み替えや画面の再読み込みで消去する。

役割を「左右で交代」にすると、コラム4と2xを交代する2セットを作る。
「同じ役割を続ける」にすると、指定した手が2xを投げ続け、反対の手が4xを返す1セットを作る。
固定役割では4分類と左右の手の選択を含む8通りを選べ、動きは1セット、同じ球まで戻る周期は3セットになる。
固定役割の4xは反対の手へ球を送るため、コラム配置の選択欄を隠す。左右交代へ戻すと、先ほど選んだコラム配置を再び使える。
「Double」では、左の4x→4、右の4x→4という4セットを作る。1・3セット目の2xと、2・4セット目の2xをそれぞれ4分類から選ぶため、16通りの組合せになる。左右の手に投げ方を固定するのではなく、4xと組む局面とコラム4と組む局面で指定する。コラム配置と左右別の選択は隠し、元の役割へ戻したときに以前の選択を保つ。
Doubleの16通りは標準の手向きで、付属VRMの左右両向きの球・手・腕の計算上の検査を通した。新しい選択欄の画面操作と描画、各組合せの実演への一致は別途確認が必要である。
Doubleの「投げる手向き」は4x側とコラム4側で別に選べる。「標準」は従来の動作を保ち、「下から支えて投げる」「クローで投げる」で投球時の手向きだけを上書きする。球と手の中心の軌道、捕球時の手向きは変えない。標準のShuffleはクロー投げなので、実演に合わせて下から投げる場合は明示する。手向きを変更した組合せは再生時にもう一度検査する。
「捕る手向き」も4x側とコラム4側で別に指定できる。標準は球の到着方向から決まり、下から受ける／クローで捕るを選ぶと、その2xを受ける手にだけ反映する。投球時の指定や4側の手向き、球と手の中心軌道は変わらない。Reverse同士のDoubleでは4種類の捕球指定を左右両向きで骨格検査した。
作った部品は列の置き換えにも、現在の列への追加にも使える。
縦の投げ、2の保持、2T、腕との関係、クロー、途中の運びは、生成した各セットで編集する。

1. 「見本から始める」で技を選び、「置き換える」を押す。
   選択欄は「3球の見本」「4球の見本」「接続の見本」「既存の技をセットに分解」に分けている。
2. 各行の左右の投げ、2xの投げ方、コラムの扱い、腕の上下を指定する。
3. 詳細欄では、腕の下で投げるか取るか、捕った後の運び、投げと捕球の座標を編集する。
   「投げ・捕りの位置を指定」の「捕球の時刻」では、通常の時刻、上昇の頂点、この球を次に投げるまでの時間に対する割合を選べる。
   頂点では捕球位置を投げ位置より高くし、高さから飛行時間を計算する。
   割合0.85は、この球を次に投げるまでの時間の85%を飛行に使う。
   保持の2には使わず、下投げの時間は落下する高さで決まるため割合指定とは併用しない。
   「手の向き」の欄では、投げと捕りをそれぞれ下から支えるか、上からつかむクローにするかを選ぶ。
   2xや4xの捕りの指定は、この球を受け取る反対の手へ適用する。
   向きを変えても、球と手の位置、経由点は変えない。
   2の保持中も向きを指定できる。
   In-line 3の手の向きも選べるが、3球を常に同じ縦線に置く配置は維持する。
   腕との関係は2x・2Tだけでなく、4・4xなどの高い投げにも指定できる。位置指定を含む見本では、腕との関係や簡易の運び方向を変えても座標と経由点を保持する。
   「持った球の途中経路」「空の手の途中経路」では、経由点を8点まで追加できる。時点と基本経路からのずらし量を指定し、方向を変更しても経由点を保持する。
4. 行の複製、並べ替え、回数指定、見本の追加で列を作る。
5. 「成立を確認して再生」で、最後から先頭までを含む周期を計算する。

「見本の開始セット」では、その技の何セット目から一周分を読み込むか選べる。
「置き換える」と「末尾につなぐ」の両方に適用し、見本を選び直すとセット1に戻る。
先頭より前にあったセットを末尾へ回すので、一周の順番と投げ方を保ったまま、別の技から入る局面を選べる。
回数指定と左右交代を必要に応じて行に展開し、上下交代クロスでは元の局面の上側の腕を保存する。
展開後の内容を保存するため、再読み込み後も作った列の開始位置を保つ。
開始位置が異なると構造コードも変わる。表示名だけで同じ入口だとは判断しない。
奇数周期にまたがる暗黙の上下交代は、各セットのクロス開始側を明示してから変更する。64行を超える展開も入力を保って拒否する。

各行の「見本の1セットを取り込む」では、見本名とその中のセット番号を選ぶ。
左・右の投げ、腕下で投げるか捕るか、クローの明示指定、クロスの開始局面を説明欄で確認してから、「このセットを置き換える」か「この後ろに1セット挿入」を押す。
3球・4球・接続の見本と既存37見本から選べるため、接続例の中間セットも再利用できる。
見本に回数指定や左右交代がある場合は、それらを展開したセット番号から1回分を選ぶ。取り込んだ行の回数は1となり、元の見本名とセット番号を記録する。
現在の列の投球間隔を保つのが初期設定である。「列全体を、この見本のセット時間にそろえる」を選ぶと、見本の間隔を列全体へ適用する。
取り込む前に両方の時間を表示し、取り込み後は列全体の球・手・腕を再検査する。

上下交代クロスを取り込むと、選んだセットの投球時にどちらの腕が上かも保存する。
たとえば見本の2番目を列の先頭へ置いても、投げ・捕りの位置を逆転させない。上下交代を維持したまま、選んだ投球局面を固定する。
各行の「このセットのクロス開始」で左腕が上・右腕が上を指定でき、「列の順番に合わせる」に戻すこともできる。
↑・↓で行を移すと、投げ・位置・運び・開始局面・回数が一緒に移る。

受け渡しが成立しない場合は、球が重なる手とセットを表示する。
球の軌道や腕の姿勢が成立しない場合は、直前の再生を保持して理由を表示する。
「動きの周期」は球の色を区別しない周期、「同じ球まで」は球の色も元へ戻る周期である。

セットの時間を変えると、重力下の飛行時間と高さが変わる。
動作だけをゆっくり観察する場合は、プレビューの「再生速度」を変える。
1セットは左右の同時動作なので、`(6,2x)`や`(2x,2x)`も1セットとして扱う。

「末尾につなぐ」は、編集している列と追加する見本の左右交代を、それぞれの区間内へ展開する。
たとえば「3種類の2xを左右交代」の6セットへBoxの2セットを追加すると、8セットになる。
各行の回数は保持し、元の見本名とセット範囲を表示する。
この名前は編集元の記録であり、個別に動きを変えた後も残る。

追加操作の後に、元の2つの列と一致する調整済みの接続見本があれば候補を表示する。
BoxとDouble Box、BoxとHF腕下、Extended BoxとLevels、HF腕下捕球のReverseとInverted型、役割固定Invertedと固定Reverse-UAIなど、登録した19組が対象となる。
候補には展開後のセット数、動きと球識別の周期、1セットの時間を表示する。「この接続見本で置き換える」を押すまで、追加した列を変更しない。
このボタンは、つなぎ区間や必要な繰り返しを含む完成した見本で列全体を置き換える操作である。読み込み後に「成立を確認して再生」で、使用中のモデルの球と腕を検査する。
一致判定では全セットの順番・回数・投げ・位置・運び・手向き・クロス開始側・テンポを比較する。名前と出典表示だけの変更は許容する。
最小の動作周期が同じでも、ユーザーが周回を増やした列を短い見本へ戻す提案はしない。回数欄や左右交代欄を展開して同じ列になる入力は同じものとして扱う。
編集を変更すると候補を消す。逆順や未登録の組合せへ、同じ接続が使えると推測して提案することはない。

追加時は、初期設定では2つの見本の短いほうのセット時間に揃える。
チェックを外すと現在の時間を維持する。
変更後の時間を表示し、「成立を確認して再生」で球と腕を検査する。
異なる球数の完成した技はそのまま連結できないため、追加前の列を保持して理由を表示する。

「球の受け渡しに必要なつなぎを補う」は初期状態で有効で、部品と見本のどちらの追加にも使える。
各区間の始まりで、空中の球が何セット後に左右どちらへ戻るかを比較する。
状態が違うときは、区間の境目と最後から先頭への戻りに、それぞれ最短セット数の投げ列を加える。
使う投げの高さは2つの元の列にある最大値までで、多重投げは作らない。
元の動作・回数・左右交代は保持し、追加した行を「受け渡しのつなぎ」として表示する。
同じ状態同士には行を追加しない。
いずれかの列がまだ単独では成立しない場合は、従来どおり行を追加して編集を続けられる。

例としてBoxの2セットに「左手が2x、右手が4x」を3回続ける区間を加えると、境目に`(4,2x)`、先頭への戻りに`(2x,4)`を補い、7セットで一周する。
見本「Box → 左手の2xを固定 → Box」でも確認できる。
つなぎも編集・保存でき、同じ球まで戻る周期は完成した列から計算し直す。
この補完が解くのは球の到着順であり、腕の通る場所やIn-lineへの配置変更は別に検査する。
空間上の接続が不成立なら、従来どおり前のプレビューを保持する。

## 動作部品の分類

2xの基本的な高さの組合せは、下から下、上から下、下から上、上から上の4種である。
縦の上投げと下投げを加えた6種を編集画面の入口にする。
受け取る手は別の軸であり、2xは反対の手、2Tは投げた手自身が捕る。
同じ手で保持する2、空の手の0は別に指定する。保持する2でも、持ったまま通る位置と次の投げまでの運びを編集できる。
6種だけで全投法を列挙したとは扱わず、以下の軸を組み合わせる。

| 軸 | 編集する内容 |
| --- | --- |
| 受け渡し | 同じ手か反対の手か、何セット先に受け取るか |
| 投げと捕り | 高さ、横位置、前後位置、反対の腕との関係 |
| 通過 | 放物線のどの時点を観察するか |
| 球を持つ手 | 捕ってから次のリリースまでの経路 |
| 空の手 | リリース後に次の球を取りに行く経路 |
| 両腕 | クロスの指定なし、左上固定、右上固定、左右交代 |
| 手の向き | 投げ、捕り、保持中をそれぞれ下から支えるかクローにするか |

コラムの入口は通常、Switched、Underarmであり、クロスの上下関係を別に指定する。
4xのxは受ける手の交替を表す。
中央コラムを縦に保ったまま反対の手へ渡す4xも作れる。
飛行中の球は放物線に従い、任意の通過点で折れ曲がらない。

High-Lowの投げ列は`(6,2x)(2x,2x)(2x,6)(2x,2x)`である。
High-Low Invertedでは、高い6と同時に投げる2xが6を上から越え、続く同時2xを6の下に通す。
Around版では、その同時2xが6を上下から挟む。
この区別は [Mike Mooreによる説明](https://jugglingedge.com/forum.php?ThreadID=2281) に基づき、球の高さの関係も自動検査する。

Extended Boxでは4xを中央の縦線に置き、もう1本のコラムが左右を交代する。
既存見本のDouble Boxは、[HFのbox + box*実演](https://drive.google.com/file/d/1I8rTL4FsXcTwFMttc4Htcp2YqtVWezDP/preview)の4セット構造に対応する。
同じ手が4x、4を続けて投げ、次の2セットを反対の手が担当する。2xは毎セット、低い位置どうしを渡す。
4xは左右へ移動するため、[Extended Boxの説明と図](https://libraryofjuggling.com/Tricks/3balltricks/ExtendedBox.html)にある中央コラムを保つ見本とは区別する。
HFの動画を0.6～3.2秒の17局面で照合した。動作の順番と投げ先の対応であり、正確な実演時刻・寸法・奥行きの再構成ではない。

「Box → Double Box（HF） → Box」は通常Boxの2セットとDouble Boxの4セットを順に置き、6セットで同じ球まで戻る。
両方の元の位置・運びを保ち、追加のつなぎセットを使わない。資料一覧のHF Double / box + box*から既存Double Boxを読み込める。
画面で組む場合は通常Boxを読み込み、Double Boxを開始セット1から末尾につなぐ。同じ構成は接続見本からも選べる。
True Boxは [参照図](https://libraryofjuggling.com/Tricks/3balltricks/TrueBox.html) に従い、縦上げ、高い横パス、縦下ろし、低い横パスの4局面をつなぐ。
球の平面を体の前に置き、空の手の戻りを前後に分けることで、交差キャッチで胸を貫かない経路を作る。

短い自己投げを使う技では、球の移動方向と受ける手を分けて記述する。
[Bizarre Box](https://libraryofjuggling.com/Tricks/3balltricks/BizarreBox.html) は、2Tを投げた手が体の反対側へ入り、腕の下で捕る。
短い球が飛んでいる間、コラムを投げた空の手がその球の下を通る。もう一方の空の手も下げ、捕球へ向かう腕の上下関係を保つ。
次の2で同じ球を持ったまま戻し、その後に2xを反対の手へ渡す。投げ列は`(4,2T)(4x,2)(4x,2x)*`である。
[Karas' Box](https://libraryofjuggling.com/Tricks/3balltricks/Karas%27Box.html) は、その持ち運びを反対向きの2Tに置き換える。
同じ手が2Tを往復させ、左右を交代して6セットで閉じる。

[Broken Box](https://libraryofjuggling.com/Tricks/3balltricks/BrokenBox.html) では、左右の手が扱う2本の縦コラムを体の同じ側に置く。
反対側から入る手が外側のコラムを腕の下で捕り、2xの局面で戻る。見本は演者の右側で、左右反転により左側になる。
[Swap Box](https://libraryofjuggling.com/Tricks/3balltricks/SwapBox.html) の高い6の下で行う同時2xは、ここでのHigh-Low Boxに対応する。

[Burst Box](https://libraryofjuggling.com/Tricks/3balltricks/BurstBox.html) は、左右それぞれのBrokenを通常のBoxの横パスでつなぐ。
腕の下から投げた手は元の側へ戻り、次の2xを捕る。`(4,2x)(2x,4x)(2x,4x)*`の6セットで、すべての4・4xは縦に飛ぶ。
[Penman's Box](https://libraryofjuggling.com/Tricks/3balltricks/Penman%27sBox.html) は、2の保持球を降下中の内側コラムの上へ回す。
その球を放さず外側へ運び、2xとして渡す。反対の手は外側の4xを腕の下から投げる。`(4x,2)(4x,2x)*`の4セットで左右を交代する。
名称を対応表で結び付け、同時2xが6より下を通ることも検査する。

[Underarm Box](https://libraryofjuggling.com/Tricks/3balltricks/UnderarmBox.html) は、腕の下から4xを投げた後、手を戻して横パスを捕る。
`(4,2x)(2x,4x)*`の4セットで、腕の下の捕球は含まない。既存のThreaded Boxとは別の見本である。
[Gilligan's Box](https://libraryofjuggling.com/Tricks/3balltricks/Gilligan%27sBox.html) は、内から外へのファウンテンと腕の下の捕球に、保持の2を加える。
球を放さず元の側へ運び、横パスを再開する。`(4,2x)(4,2)(2x,4x)*`の6セットで閉じる。

[Levels](https://libraryofjuggling.com/Tricks/3balltricks/Levels.html) は`(4x,2x)(4,2x)*`のExtended Boxを三段に変形する。

両方向に20セットの移行を置き、先に中央コラムを前へ分け、その後に高さと捕球時刻を段階的に変える。

## 名前と保存データ

**表示名**は自由な名前であり、変更しても動作の識別には影響しない。
**保存内容の識別子**は`3B-S4-C12-xxxxxxxx`の形式とし、球数、動きの最短周期、同じ球までの周期、保存内容から計算した短いIDを含める。
短いIDだけで同一性を確定せず、正確な比較には構造コード全体を使う。

**構造コード**は`SYNC1:`に続く正規化済みJSONである。
名前を除いた投げ列、動作、時間を記録し、重複するセット列は最短周期へ縮める。
開始位置のずらしや全体の左右反転は、自動的に同じ名前へまとめない。
既存名の別名は、出典とセットでカタログに記録する。
Henry FisherのBoxとBox*の星印も、出典の表記を維持する。

検査済みの部品を並べる**接続列の保存識別子**は、`3B-R38-C114-xxxxxxxx`の形式とする。Bは球数、Rは選んだ接続列のセット数、Cは実際の接続状態と球の置換から求めた同じ球までのセット数である。Rは最短の動作周期へ縮めず、選んだ並びをそのまま数える。末尾から先頭への接続や周期の上限を確認できない列ではCを`pending`とし、空の列でも周期成立とは表示しない。

接続列の構造コードは`SYNC-ROUTE1:`に続く正規化済みJSONである。登録元の全定義・登録順・左右反転と、使用するセットの並びを含む。列に直接出てこない登録元も、後から登録する動作の肘の入口合わせに使われる場合があるため残す。そのため、登録元を追加しただけでも内容IDは変わり得る。表示名、元の見本名、各行の出典名、移行用という表示上のラベルは除く。JSON内の項目の記載順は識別に影響しないが、セットや登録元の配列順は保持する。

接続列の「詳細：1セット単位の操作・構造コード」に保存内容の識別子と正確な内容を表示する。保存ファイル名は「呼び名.json」とし、呼び名が空なら動作の並びを使う。保存形式は従来のversion 1のままで、構成名や自己申告の検査結果を読み込み時の成立証明には使わない。構成名は再現用の定義を識別するもので、異なるVRMや検査条件で同じ姿勢になる保証ではない。
名称変更と内容変更の区別、開始位置を変えた38セットの列、左右反転、保存復元は[接続列の命名検査](verification/sync-route-naming-audit.json)の29件で確認した。通常向きの例は`3B-R38-C114-14c621c6`、左右反転は`3B-R38-C114-f03162d3`となり、保存復元後もそれぞれ同じ識別子に戻る。現在の呼び名ベースのファイル保存と復元は、上記のモード分離の実画面検証で確認した。

JSONファイルには`version: 1`、表示名、1拍の時間、左右交代の指定、セット列を保存する。
各行の任意の`sourceName`には元の見本名を保存し、構造コードと周期の判定からは除外する。
各手の`releaseGrip`と`catchGrip`には`underhand`または`overhand`を保存し、省略時は既存の自動判定を使う。
これらは動作の指定なので構造コードに含める。
上下交代クロスの`motion.armPhase`は投球時の上の手を0（左）または1（右）で保存する。省略時は従来どおり列の順番で交代する。`armOrder: alternate`と組み合わせて使い、構造コードにも含める。
2の保持には`releaseGrip`を使う。
位置定義の`catchAtApex: true`は頂点捕球、`flightFraction`は次の投げまでの飛行時間の割合を表す。
両方の同時指定を拒否し、捕球後の時間が不足する場合や、手の受け渡し順が崩れる場合も再生を認めない。
編集中に受け渡しが不成立でも保存し、読み込み後に該当箇所を修正できる。
入力は64行まで、各行の繰り返しは16回まで、展開後と球識別の周期は128セットまでとする。

### 相対的な通過順から動作と接続を生成する

基本の2xは進行方向に沿って先に通る球・後に通る球との関係で定義する。Normalは下→下、Shuffleは上→下、Reverse Shuffleは下→上、Invertedは上→上となる。「球同士の接触を許可する」を選んでも、この通過順と腕・胴体・到達範囲の測定は残る。接触を再生停止の条件にするかは、以下の生成方式で区別する。

生成処理は、投げる位置・捕る位置・滞空時間・捕球後の運び・空いた手の戻りを共通の変数として扱う。左右の手の移動と腕の経路を一緒に評価し、周期末から先頭への連続性も検査する。数値的な探索の初期候補は技名で選ばず、候補ごとに現在の定義とモデルで検証する。

接続時は、登録済みのAとBを保持したまま準備区間を生成する。その区間では将来の捕球位置と次の投球位置を合わせ、投げと捕りの手向きも引き継ぐ。A・Bそれぞれの球、手、腕を含む境界状態に一致し、往復とも接続できた場合にだけ登録する。保存ファイルには探索後の位置・時間・運びを記録するため、読み込み時に元の推測配置へ戻らない。登録後の繰り返しは確認済みの接続部品を再利用する。

固定Crossの上になる腕の左右と左右反転を含む64通り、生成したCrossと通常Boxの往復、保存・復元・再利用の確認は[検査記録](verification/sync-contact-and-transition-audit.json)を参照する。これは記録に列挙したケースの確認であり、任意の数値を持つ無限の入力すべてを証明したという意味ではない。

Crossと縦の2xを組み合わせると、腕の重なる位置が体の中央から横へ移る。上下関係は両腕の横方向の共通範囲で判定し、共通範囲がない瞬間には交差の上下を強制しない。腕同士の距離、球・胴体との間隔、関節の曲げ方、周期全体の連続性は別々に維持する。名前で選んだ縦投げは投球と捕球のX・Z座標をそろえ、腕の上下用の奥行き補正で斜めにならないようにする。

基本モードの生成はWeb Workerで行い、計算中も視点・再生操作と「生成を中止」を使える。編集内容は生成前に保存し、計算結果が出るまで直前のプレビューを保持する。結果は現在と同じVRMの骨格で測定し、モデルと手の到達位置の一致を再確認してから表示へ反映する。中止した処理の遅い結果は反映しない。Cross InvertedとOutside column Upの厳密方式による左右入替・鏡像、縦軸と通過順の確認は[検査記録](verification/sync-cross-vertical-audit.json)を参照する。

### 短時間で生成し、接触が残っても再生する

Composerでは `syncPlanningMode='constructive'` を使う。個別の技名を持つ例外は追加せず、直接移動、小さな円の両方向、引いて下へ差し込む両方向の最大5候補を比較する。手の補正は投げ・捕りで位置と速度がゼロになり、飛行中の球の軌道を変更しない。In-line 3では球を持つ手に横方向の補正を加えない。

肘は固定数の候補から周期の継ぎ目を含む経路を一度だけ選び、周期方向の平滑化で急な回転を抑える。厳密探索や角度の再細分化へは戻らない。接触・胴体との干渉・姿勢の目安を満たさない部分は測定値に残し、「簡易再生」と明示する。`skeletonOK` は従来の厳密基準のままで、接触を許す `playbackOK` と区別する。有限の座標と手の到達誤差12 mm未満は再生条件として維持する。数学的に成立しない球の受け渡しは引き続き拒否する。

A→Bでは実際に登録した投球・捕球位置から共通の引き込み／円運動／直接移動を組み立てる。候補数は最大3で、両方向の球・手・腕の境界が一致してから登録する。元のA・Bは変更しない。保存には生成方式と独立した経由点を含め、復元時に経路を重ね直したり厳密探索へ戻したりしない。既存の厳密方式の保存文書は、その方式を保持する。
