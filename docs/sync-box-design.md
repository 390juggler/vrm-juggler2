# コラム4と2の動作から組み立てる同期ボックス

## 基準となる考え方

**縦に動く4側のコラムと、2側の動きのバリエーション**を組み合わせる。
コラムをどこに置き、どちらの手で投げて取るか、その間に2をどう投げ、取り、運ぶかを一組の動作として扱う。
同じサイトスワップでも、この動作が違えば別のバリエーションになる。

基準は3ボールの同期ボックスである。
サイトスワップは球の担当と受け渡し時刻を照合するために添える。
ここでいう「2側」は短い側の動作の総称であり、実行データでは同じ手の2と別の手へ渡す2x、保持と投げを区別する。

**コラムの位置と、担当する手を分離する。**
左のコラムを右手が担当することも、手が移動して縦の球を別の手で取ることも考えられる。
4xや2xのxは手の交替を表し、画面内の横移動や腕のクロスを直接指定するものではない。
関連するシャワー側も、高い球の軌道を記号だけから決めず、縦を保つ形と横に送る形を分けて扱う。

この分類をもとに、別画面の同期ボックス版を実装した。
起動方法、実装した範囲、検査結果は [同期ボックス版の使い方](sync-box.md) を参照する。
名称、出典、組合せ候補は [名称カタログ](sync-box-catalog.json) に記録した。

## 動作の四段階

ユーザーの定義は **投げる位置 → 通る位置・経路 → 捕る位置 → 次の投げる位置への移動**。
最初の位置は「捕る位置」ではなく「投げる位置」である。
投げ・捕りには時刻、担当する手、手の向き、反対の腕との関係を持たせる。
飛んでいる球は重力のある放物線を保ち、通過点を理由に途中で曲げない。
捕った球を運ぶ経路と、投げ終わった空の手が次の捕球へ動く経路は別に定義する。

上投げ・下投げの通過位置はボールの間に限定しない。縦2xには中央・外側・反対側を用意し、
2xを腕の下から投げる条件と、腕の下で捕る条件を分ける。
クロスは左上固定・右上固定・左右交代を別の状態として扱う。

## 動作を分ける五つの軸

| 軸 | 記録する内容 | 対応するバリエーション |
| --- | --- | --- |
| コラム | 空間上の位置、投げる手、取る手、腕の上か下か | 通常、スイッチド、コラムを腕の下で取る形 |
| 2側 | リリースとキャッチの位置、投げるか保持して運ぶか | Normal、Shuffle、Reverse Shuffle、Inverted、縦2x |
| 腕の配置 | 開いた状態、左右どちらが上か、前後関係、交差と解除の時期 | クロス、Under-arm、Reverse Under-arm |
| 手の向き | 手のひら、クロー、投げと取りの間の回転 | UA-Clawなど |
| 繰り返し方 | コラム役と短い側の役を交替するか、部品をどうつなぐか | ボックス、同期シャワー、Double Box、Box Roll |

リリース時だけでなく、キャッチ後から次のリリースまでの手の移動を含める。
たとえばスイッチドを左右の座標交換だけで定義すると、担当する手の移動が欠ける。
Under-armも球の端点だけでは決まらず、どの局面でどちらの腕の下を通るかが必要になる。

## 2側の基本四種

「上／下」は投げ・捕りの高い位置と低い位置の区別を示す。
通過時にコラムの球とどちらが上になるかは、位置とタイミングの結果であり固定条件にしない。
以下は参照PDFの概略であり、端点だけで投法を完全に定義するものではない。

| 動作部品 | 投げ側 → 受け側 | 着目する動き |
| --- | --- | --- |
| Normal | 下 → 下 | 通常の横の受け渡し |
| Shuffle | 上 → 下 | 手を上げ、反対側へ斜め下に投げ込むSlam |
| Reverse Shuffle | 下 → 上 | 斜め上へ送り、受ける手を上げる |
| Inverted | 上 → 上 | 高い位置どうしを結ぶ |

片方向と戻り方向の2側を選ぶと、次の候補表になる。
左右反転と開始位相の違いは、元のパターンへの対応を残す。

| 片方向 ＼ 戻り | Normal | Shuffle | Reverse Shuffle | Inverted |
| --- | --- | --- | --- | --- |
| Normal | Box | 候補 | 候補 | 候補 |
| Shuffle | 候補 | Luke's Shuffle / Drop Box | N-Box | 候補 |
| Reverse Shuffle | 候補 | N-Box | 候補 | 候補 |
| Inverted | 候補 | 候補 | 候補 | Inverted Box |

名前のある欄は参照PDF 3ページの対応である。
「候補」は、この二つの動作を接続できるか調べる欄であり、実演済みの技や既存の名称を意味しない。
前の動作の終わりにある両手と球の状態が、次の動作の始まりにつながるかを確認する。

## 資料にある9分類と二つの系統

Henry Fisherの体系では、コラム側または高い側と2側、手と球の配置を合わせた動作部品に名前が付いている。
以下の18項目は、参照PDF 2ページと [Juggling DatabaseのThrows](https://henfish.github.io/juggling-database/throws.html) の掲載名を保持したもの。
作者による命名を含むため、一般名と出典の名称は別に保存する。

| 分類 | 資料の `(4x,2x)` 側 | 資料の `(4,2x)*` 側 |
| --- | --- | --- |
| 基本形 | Box | Box* |
| シャッフル | Shuffle | Shuffle* |
| リバースシャッフル | Reverse-Shuffle | Reverse-Shuffle* |
| インバーテッド | Inverted-Box | Inverted-Box* |
| アンダーアーム | UA-Box | UA-Box* |
| リバースアンダーアーム | Reverse-UA-Box | Reverse-UA-Box* |
| アンダーアームインバーテッド | UAI-Box | UAI-Box* |
| リバースUAインバーテッド | Reverse-UAI-Box | Reverse-UAI-Box* |
| アンダーアームクロー | UA-Claw-Box | UA-Claw-Box* |

UAはUnder-Arm、UAIはUnder-Arm-Invertedの略。
名称中の星印は原表記を維持する。
同サイトのBox*の参照先は一般的なBox、Boxの参照先はShowerである。
Shuffle*はLuke's Shuffle / Drop Box、Inverted-Box*はInverted Boxに対応する。

リンク先と同期タイミングまで同一とは限らない。
たとえばShuffleの参照先はLibrary of Jugglingでは非同期の51であり、動作の参考先として区別する。
対応は [公開データ](https://github.com/henfish/henfish.github.io/blob/main/juggling-database/data.json) に基づく。

Under-arm系の「どの球を、どちらの腕の下から投げる／取るか」は、名称だけでは確定しない。
Reverseを動画の単純な逆再生、Invertedを座標の上下反転として実装しない。
各部品について、投げる局面、取る局面、腕をほどく局面を実演と照合してから定義する。

## 指定された追加バリエーションの扱い

| 項目 | コラムと2側のどこが変わるか | 参照と設計上の扱い |
| --- | --- | --- |
| シャワー | 高い側と短い側を送る役割と受け渡し先 | 同期シャワーを関連系として含め、物理的な縦軌道か横移動かは別に記録する |
| ボックス | コラム役と2側の役を交替 | 通常形を比較の基準にする |
| スイッチド | コラムを担当する手 | 反対側の手が各コラムを担当し、両手が移動する |
| クロス | 腕の配置と交差の切替 | 左腕が上か右腕が上か、どの局面で交差するかを独立に指定する |
| アンダーアーム | 投げまたは取りと、もう一方の腕との関係 | コラム側か2側か、投げか取りかを分けて指定する |
| シャッフル | 2側の上から下への送り | コラムと両手の移動を伴う動作部品として定義する |
| リバースシャッフル | 2側の下から上への送り | 次のキャッチと運びまで含める |
| インバーテッド | 2側が高い位置から高い位置へ渡る | 高い位置への手の移動と、コラムの投げ取りを接続する |
| 縦に投げる2x | 短い球の軌道と受ける手の移動 | 同じ空間位置で別の手に受け渡す形を含め、上向きと下向きを候補として分ける |

[Switched Box](https://libraryofjuggling.com/Tricks/3balltricks/SwitchedBox.html) は、反対側のコラムを担当する動きの参照例である。
周期全体を腕の交差固定として扱うと、この手の移動を失う。
「クロス」は腕の状態として独立に保存し、スイッチドやサイトスワップのxと同義にしない。
Henry Fisherの公開データにあるCrosses*も参照先として保存したが、ユーザーのいうクロスとの厳密な一致は未確定である。

[Threaded Box](https://libraryofjuggling.com/Tricks/3balltricks/ThreadedBox.html) はコラムをもう一方の腕の下で取る形の参照になる。
Henry FisherのUA系列のどの名称に対応するかは、同一視せず実演で確認する。

[True Box / Box with a Lid](https://libraryofjuggling.com/Tricks/3balltricks/TrueBox.html) は縦方向の2xを含む参照例である。
縦2x全般の別名にはしない。
新しい候補では、投げた球を受ける位置に反対の手が移動する区間まで定義する。
保持して運ぶ2と、手から離れて飛ぶ2xは別の状態として扱う。

## 組合せを広げる範囲

まず通常のコラムを保った基本四種の2側を比較し、次にコラム担当の交換、腕のクロス、Under-arm、縦2xを組み合わせる。
すべての軸の総当たりを「実行できるパターン数」とは数えない。
両手の到達範囲、腕の上下関係、球の通り道と次の投げまでの時間が両立する組合せを選ぶ。

作者の [Tricks](https://henfish.github.io/juggling-database/tricks.html) にはDouble Boxの9×9の組合せ表がある。
こちらは `(4x,2x)` 側と `(4,2x)*` 側の動作部品をつなぐ表であり、上の基本四種の往復表とは用途が違う。
参照した公開表の81欄をカタログに保存し、14欄の実演リンク付き印と空欄を区別した。
作者の実演リンクがあることは、こちらで動作を検証したことを意味しない。
空欄は未掲載として扱い、不可能とは判定しない。

Box Roll variation 2の `(4,2x)(4,2)*` は、コラムと2の保持／運びを含める拡張候補として記録した。
2を機械的にすべて保持扱いするか、投げや運びを加えるかは、動作部品ごとに指定する。

## vrm-juggler2に渡す動作設計

一つの部品に、コラム側、2側、両腕の状態をまとめて持たせる。
動作の入口は「投げる → 通る → 捕る → 次の投げへの運び」とする。
それぞれに球の識別、担当する手、位置、手の向き、腕の上下と前後関係を記録する。
隣の部品とは、球の担当と手の位置、速度、腕の状態が連続するように接続する。

| 元の入口 | 確認した制約 | 同期版への設計 |
| --- | --- | --- |
| `src/presets.ts` の `PatternPreset` | サイトスワップと名称が中心 | 同じサイトスワップに複数の `motionId` を持たせる |
| `src/motion/juggling/natural.ts` の `styleKey` | 形の選択対象が3以上の投げ | 2側にも専用の動作部品を指定できるようにする |
| 同ファイルの `keepOut` | ボールでも投げ取りなどの位置を手の自側へ制限 | 新しい動作経路では、反対側を担当する手の位置を表現できるようにする |
| `src/motion/body/index.ts` の `solveArm` | 肘の向きに左右の腕と道具種別を主に使う | 位相ごとの交差、上の腕、下の腕を肘の制御にも渡す |

実装時は同期ボックス用の動作生成経路を追加し、既存の球の担当とタイミングの計算を利用する。
球が飛んでいる区間は重力を含む軌道、握っている区間は手に追従する軌道として扱う。
Invertedでも重力を反転させず、リリースとキャッチの位置、速度、手の移動を設計する。
動作の繰り返し周期は、サイトスワップの最短周期より長くなる場合も許容する。

### 実装の段階

1. 通常のBoxを基準に、コラムと2xの同時リリース、3球の連続性を確認する。
2. Drop Box、N-Box、Inverted Boxで2側の四種と両手の移動を作る。
3. Switched Box、クロス、Threaded Boxでコラム担当と腕の配置を分離する。
4. True Boxを参照し、縦2xの送りと受ける手の移動を作る。
5. 同期シャワー、UA系列、Double Box、Box Rollへ部品の接続を広げる。

### 動作を採用する際の確認

- 常に3球を保ち、球の担当が途切れず、リリースとキャッチで手と球の位置が合う。
- 狙った区間でコラムが縦に動き、2側が指定した経路を通る。
- 腕の交差の上下と前後が一致し、手と肘に不連続な移動がない。
- 球と腕が意図せず貫通せず、アバターの可動範囲内で成立する。
- 周期のつなぎ目で球、手、腕の状態が連続する。
- 正面と斜めからの再生で元の実演と照合し、左右反転も確認する。

## 手と肘の姿勢

投げる時は送り出す方向、捕る時は球が来る方向へ手のひらを向ける。
指先はその方向と前腕の延長を両立させ、手首が後ろへ折れる向きは避ける。
上向き・下向きに手を返す途中の経路も指定し、前腕のひねりはクォータニオンで連続させる。
角度を±180度で折り返してから一部だけ掛ける処理は、境界で反転するため廃止した。

肘は体側で下がる位置を優先し、手が外へ動くことと肘が外へ張ることを分離する。
Switchedでは内向きの肘の基準を使い、腕・球との間隔を保ちながら周期全体の経路を決める。
離散的な肘の候補を選んだ後、骨の長さを保ったまま経路を滑らかにする。
数値での連続性と、画面での姿勢の自然さは別に確認する。
