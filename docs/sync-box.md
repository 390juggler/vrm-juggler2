# コラムと2：同期ボックス版

`390juggler/vrm-juggler2` のブラウザー版を基にした、コラム4と短い2側の動きを組み合わせる3ボール用画面。

技を分解して接続する画面は [セット列の作成](sync-compose.md) を参照。
同期ボックス画面の「セットで組む」から開ける。

## 起動と操作

このフォルダーの `start-sync-box.cmd` を開き、<http://127.0.0.1:8080/sync-box.html> にアクセスする。
依存パッケージがなければ `npm install`、TypeScript変更後は `npm run build` を実行する。

- プリセット、左右反転、再生・停止、コマ送り、周期内の位置を選ぶ。
- 正面・斜め・横・寄りで確認する。ドラッグで回転、ホイールで拡大できる。
- 「投げ・通過・捕り・運びを編集」でコラムの担当、2xの高低・縦の位置・lateral・腕の下での投げ／捕り・運び方を組み合わせる。
- クロスは左上固定・右上固定・左右交代から選ぶ。
- 「4段階の位置を確認」のボタンで投げ・通過・捕球・同じ球の次の投げへ移動する。
- 「1周期の骨格を検査」で現在のモデルを調べる。一括検査では37種と左右反転を検査しJSONを保存できる。
- 「自分のVRMを読み込む」でモデルを変更できる。体格を変えた場合は表示と骨格検査を再確認する。

通常版は右上のリンクから開ける。同期版は3ボールに固定し、身体の揺れを止めている。
基本のコラムの上がり幅は約39cm。高さは24〜60cmで指定でき、それに合わせて投げの間隔も変わる。
速度の変更は全体のスロー再生であり、球の高さを変えない。

## 動作の定義と実装範囲

**投げる位置 → 通る位置・経路 → 捕る位置 → 次の投げる位置への移動**。
飛行中の球は重力に従い、保持中の球は手に追従する。空の手が次の捕球へ動く経路も別に持つ。
通過点を途中の曲がり角としては扱わない。上投げ・下投げの通過場所をボールの間に限定しない。

37プリセットを収録した。

| 系統 | 内容 |
| --- | --- |
| 基本 | Box、Shuffle往復、N-Box、Reverse往復、Inverted |
| Switched | 通常、高→低のSlam、低→高のReverse Slam、高→高 |
| 縦2x | 中央・外側・反対側 × 上投げ・下投げ × 通常コラム・Switched |
| lateral | Normal・Shuffle・Reverse・Inverted |
| 腕との関係 | クロス左上・右上・交代、コラムのUnder-arm、2xのUnder-arm投げ・捕り |
| 関連系 | 同期Shower、Shower × Shuffle、Double Box、Box Rollの保持接続 |
| 縦一列 | In-line 3、2xを一番上に置く派生候補 |

2は同じ手での保持、2xは別の手への飛行として区別する。縦2xも同じx/z位置で別の手へ渡す。
縦下ろしは初速0で落とし、両手のリリースを同期させたまま受け取り時刻を調整する。
In-line 3は保持中も飛行中も3球のx/z座標をそろえ、常に同じ縦線上に置く。
中央の2xと上下の4で構成し、空の手だけが列の外を回る。前後へ球を分けていた解釈を修正した。
捕球の沈み込みも含めて上下間隔を確保し、保持時間を短くして空の手の移動時間を取る。標準の4の上がり幅は24cm。
既存のInverted候補は2xを一番上に置く構成とした。参照名や派生候補の細部は実演との完全一致を保証しない。
UA系列の全名称、True Boxの完全なシーケンス、Double Box全81通りは再現対象に含めていない。
出典と分類は [設計資料](sync-box-design.md) と [名称カタログ](sync-box-catalog.json) に記録した。

## 手・肘・顔の修正

肘は体側で下がった位置を優先する。Switchedでは肘を内へ寄せたまま前腕を外へ動かす。
手は投げる方向・球が来る方向へ向け、指先が前腕側へ折り返さないようにする。
手を返す経路と前腕のひねりを連続させ、±180度の境界で急に反転する処理を修正した。
周期全体で腕と球の間隔を確保し、離散的な肘の候補を滑らかな経路へ整える。

肘が裏回りして胴体を通る問題に対し、胴体を覆う楕円体と腕の線分の交差、肘の前後・左右・高さ、
肘の折り畳みと手首の折り返しを共通の制約に追加した。以前の「確認OK」にはこれらの姿勢判定がなかった。
制約は候補選択・経路の平滑化・再生時の補間に適用する。1周期の補間も3ms以下で事前検査する。
経路が成立しないときに制約なしのIKへ戻す処理をやめ、編集時は直前の配置を保持する。
高い中央の手には腕の向きに合った指先方向を使い、空手の経路へ暗黙に奥行きを足す処理も取り除いた。
各派生形の位置・保持中の運び・空手の戻りは、球の干渉と腕の制約を両方満たすように調整した。
到達距離は球の中心を腕長と比較せず、手の向きとモデルの手の寸法から求めた手首位置で確認する。

見上げたときの目の下の線は、付属VRMの顔の輪郭描画を切り替えて原因を切り分けた。
顔の内側にある輪郭マスクの薄い部分を描画時に抑える。VRM本体・元画像・アイライン材質は変更しない。
この補正は付属VRMの顔の輪郭材質に限り、読み込んだ別モデルには適用しない。

## 検証

2026-10-14のセット編集版では自動テスト861件と、接続例の左右反転42件を加えた骨格132件が通った。
ブラウザーでは接続例21種とIn-line接続以降の12種の左右反転、計33件を再生して周期検査した。
以下の測定値と74件のブラウザー検査は、既存見本の受け入れ基準として保持する。

2026-10-13のIn-line 3修正版で、`npm run typecheck`、`npm run build`、自動テスト730件が成功した。
実際の付属VRMの骨格で37種×左右反転74件と基本四種の往復16件、計90件を検査した。
ブラウザーでも37種×左右反転74件を検査し、要確認は0件だった。
In-line 3は正面0%と横37.5%、上段2xの候補は斜め62.5%の表示を確認した。
全周期・左右反転で3球の横幅と奥行き幅が1e-10m未満、上下順が変わらず球同士が離れていることを検査した。
保持中の球を列から外す編集の拒否も検査した。
前回はクロス左上の正面0%と斜め25%・75%、アンダーアームの斜め55.3%と横25%・75%、
成立しないクロスのInverted／Normalの編集を拒否して直前の動作を保つことを表示で確認した。
通常版の3ボールと531・クラブ、顔の見上げ表示は前回修正時に確認済み。今回それらの見た目は変更していない。

| 手と球の最大ずれ | 0.000001 cm未満 |
| 腕の骨同士の最小間隔 | 7.77 cm |

Switchedでは周期を通して肘が肩より26.2cm以上低く、体の中心から横へ17.4cm以内に収まる。
肘の最大速度は3.17m/s未満。手のひらと指先の目標方向も実際の骨の回転と照合した。
固定クロスの上下、交代クロスの両方向、Under-arm投げ／捕りの反対の前腕との位置関係を検査している。

骨格検査は4ms以下の間隔、肘の経路計画は1周期120点から始める。
補間中に制約を満たせない場合は240点、480点で再計算し、同じ制約で検査する。
手首に近い前腕の末端20%は球を持つ接触領域として距離判定から除外する。
数値上の間隔・連続性と、人間らしい姿勢、指・衣服のメッシュの干渉、既存の技名との一致は別の確認事項である。
姿勢の制約値は正面でジャグリングするための保守的な作業範囲であり、人体全般の医学的な可動域ではない。
自由な組合せや高さの変更をすべて実演可能と判定するものではない。不成立の配置は再生せず、設定の調整を促す。
別VRMでの表示・ファイル選択は未検証。
